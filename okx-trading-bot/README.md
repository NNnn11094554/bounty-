# 🤖 OKX Trading Bot — бессрочные фьючерсы USDT-M

Бот для автоматической торговли бессрочными свопами (USDT-M perpetual swaps) на OKX через официальный
API v5 (библиотека ccxt). Работает 24/7 без участия человека: сам анализирует рынок, открывает и закрывает
позиции, ставит стоп-лосс и тейк-профит на бирже, ведёт трейлинг-стоп, переживает обрывы сети и перезапуски,
шлёт уведомления и принимает команды в Telegram.

> ⚠️ **Риски.** Торговля фьючерсами с плечом может привести к потере всего депозита. Бот не гарантирует
> прибыль. Сначала работайте в **DEMO** (включён по умолчанию), прогоните бэктест на реальной истории и
> переходите на реальный счёт только с суммой, которую готовы потерять.

## Что умеет

- **Режимы:** DEMO (по умолчанию, заголовок `x-simulated-trading: 1`), LIVE (только явным `LIVE_TRADING=true`
  в `.env`), бэктест на истории OKX.
- **SL/TP на бирже сразу при входе:** рыночный ордер уходит с прикреплёнными algo-ордерами OKX
  (`attachAlgoOrds`), то есть стоп и тейк появляются на бирже одновременно с позицией. Если бот упадёт,
  позиция останется защищённой.
- **Трейлинг-стоп** после +1 ATR: стоп на бирже переносится (`amend-algos`) по ценам из WebSocket.
- **Сверка с биржей** каждые 30 секунд: найденные позиции без записи в БД берутся на сопровождение, дубли
  не открываются, пропавший SL/TP выставляется заново, закрытые на бирже сделки записываются с PnL.
- **Риск-менеджмент:** 1% риска на сделку (объём считается от расстояния до стопа с учётом комиссий),
  максимум 2 позиции, дневной лимит убытка 5%.
- **Telegram:** уведомления о сделках, PnL, ошибках, дневном лимите; команды `/status /stop /start /closeall
  /report`. Отвечает только владельцу (ваш `chat_id`).
- **Надёжность:** повторы с экспоненциальной задержкой, учёт rate limit OKX, защита от дублей ордеров при
  таймаутах, WebSocket с запасным REST, watchdog, `restart: always`, логи с ротацией, все сделки в SQLite.

## Стратегия по умолчанию

`ema_cross`, таймфрейм 15m, пары BTC-USDT-SWAP и ETH-USDT-SWAP. Все параметры лежат в `config.yaml`.

| | Условие |
|---|---|
| **Лонг** | EMA 9 пересекает EMA 21 снизу вверх **и** цена закрытия выше EMA 200 **и** RSI(14) < 70 |
| **Шорт** | EMA 9 пересекает EMA 21 сверху вниз **и** цена закрытия ниже EMA 200 **и** RSI(14) > 30 |
| **Стоп-лосс** | 1.5 × ATR(14) от цены входа |
| **Тейк-профит** | 3 × ATR(14) (риск/прибыль 1:2) |
| **Трейлинг** | включается после движения на +1 ATR. Стоп держится в 1 ATR от лучшей цены, поэтому при включении он оказывается в безубытке (`trailing_distance_atr`) |
| **Плечо** | 3x, маржа isolated |

Сигнал считается только по **закрытым** свечам, через несколько секунд после закрытия бара. Вход по рынку.
SL/TP пересчитываются от фактической цены исполнения. Если по инструменту уже есть позиция, новый сигнал
пропускается. Можно включить закрытие позиции по встречному сигналу (`close_on_opposite_signal`).

## Риск-менеджмент

- **Размер позиции:** `риск = 1% equity`. Количество подбирается так, чтобы убыток при срабатывании стопа
  **вместе с комиссиями входа и выхода** не превышал риск. Объём округляется вниз до шага лота (`lotSz`),
  цены — до шага цены (`tickSz`). Оба шага, `ctVal` и `minSz` берутся из `/public/instruments`. Если объём
  меньше минимального контракта, сделка пропускается с уведомлением.
- **Маржа:** под одну позицию уходит не больше 90% свободной маржи. Если её не хватает, объём урезается (риск
  становится меньше 1%). Если OKX всё равно ответит «недостаточно маржи» (51008), бот повторит вход с меньшим
  объёмом. Если стоп оказался бы дальше цены ликвидации, вход отменяется.
- **Максимум позиций:** 2 одновременно, по одной на инструмент.
- **Дневной лимит:** если equity упало на 5% от значения на начало дня (UTC), новые сделки не открываются до
  следующего дня. Открытые позиции сопровождаются дальше со своими SL/TP. Состояние лимита хранится в БД
  и переживает перезапуск. Учтите: вывод средств со счёта бот тоже увидит как падение equity.

## Безопасность и API-ключ OKX

> 🔐 **API-ключ OKX должен иметь только право «Trade» (и «Read»), БЕЗ права «Withdraw», и быть привязан
> к IP-адресу вашего сервера.** Тогда даже при утечке ключа вывести средства с него нельзя, а пользоваться
> им можно только с вашего сервера.

- Все секреты (API key, secret, passphrase, токен Telegram) хранятся **только в `.env`**. Файл `.env` уже
  в `.gitignore` и `.dockerignore`, не коммитьте его. Шаблон — `.env.example`.
- На сервере выставьте права: `chmod 600 .env`.
- Секреты вырезаются из логов. Контейнер работает от непривилегированного пользователя.
- Бот отвечает в Telegram только на ваш `TELEGRAM_CHAT_ID`, сообщения от остальных игнорирует.
- Входящие порты боту не нужны: на VPS можно закрыть всё, кроме SSH.

**Как создать ключ для DEMO:** OKX → Trade → **Demo trading** → профиль → **Demo Trading API** → Create
API key. Права: Read + Trade. IP: адрес сервера. Задайте passphrase.
**Для LIVE** ключ создаётся отдельно в обычном режиме: профиль → API → Create API key, с теми же правами
(Read + Trade, **без Withdraw**) и IP-привязкой. Демо-ключи на реальном счёте не работают, и наоборот.

**Настройки аккаунта OKX:** режим аккаунта должен поддерживать фьючерсы (Settings → Account mode → *Futures*
/ *Single-currency margin*; в режиме *Spot* свопы недоступны). Режим позиций подойдёт любой: One-way (net)
или Long/Short. Бот определяет его сам.

## Запуск на VPS (Ubuntu) — пошагово

Хватит самого простого VPS: 1 vCPU, 1 ГБ RAM, Ubuntu 22.04/24.04. Желательно в регионе, где OKX доступен.

**1. Подготовка сервера**

```bash
sudo apt update && sudo apt upgrade -y
sudo timedatectl set-ntp true          # точное время обязательно: OKX отклоняет запросы при расхождении > 30 с
sudo ufw allow OpenSSH && sudo ufw --force enable   # входящие порты боту не нужны
```

**2. Установка Docker**

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER          # затем перелогиньтесь (exit и снова ssh)
docker compose version                 # проверка
```

**3. Код бота**

```bash
git clone https://github.com/nnnn11094554/bounty-.git
cd bounty-/okx-trading-bot
mkdir -p data logs reports && sudo chown -R 1000:1000 data logs reports
curl -4 ifconfig.me                    # IP сервера — укажите его при создании API-ключа OKX
```

**4. Секреты.** Создайте API-ключ OKX (см. раздел выше) и Telegram-бота:
- откройте [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен;
- узнайте свой `chat_id` у [@userinfobot](https://t.me/userinfobot);
- напишите своему новому боту любое сообщение, иначе он не сможет вам писать.

```bash
cp .env.example .env
nano .env                              # впишите ключи OKX, токен и chat_id; LIVE_TRADING=false
chmod 600 .env
```

**5. Проверка** ключей, связи с OKX, WebSocket и Telegram (в Telegram придёт тестовое сообщение):

```bash
docker compose run --rm bot check
```

**6. Запуск**

```bash
docker compose up -d --build
docker compose logs -f                 # или: tail -f logs/bot.log   (выход из просмотра — Ctrl+C)
```

Всё. `restart: always` поднимет бота после сбоя и после перезагрузки сервера (Docker стартует сам).
Сделки хранятся в `data/bot.db`, логи с ротацией лежат в `logs/`.

**Полезные команды**

```bash
docker compose ps                      # статус (healthy / unhealthy)
docker compose restart                 # перезапуск, например после правки config.yaml или .env
docker compose down                    # остановка (позиции остаются на бирже со своими SL/TP!)
git pull && docker compose up -d --build   # обновление бота
docker compose run --rm bot backtest   # бэктест за 6 месяцев, отчёт в reports/
cp data/bot.db ~/bot-backup-$(date +%F).db  # резервная копия истории сделок
```

## Telegram: уведомления и команды

Уведомления: запуск и остановка бота, открытие сделки (вход, объём, SL/TP, риск), включение трейлинга,
закрытие (причина, PnL, R), ошибки (не чаще раза в 15 минут на одну и ту же), срабатывание дневного лимита,
итоги дня, найденные или восстановленные позиции и SL/TP.

| Команда | Действие |
|---|---|
| `/status` | баланс, свободная маржа, PnL за день, открытые позиции с uPnL, SL/TP, трейлинг |
| `/stop` | пауза: новые сделки не открываются, открытые сопровождаются (SL/TP, трейлинг) |
| `/start` | возобновить торговлю |
| `/closeall` | закрыть все позиции и отменить все ордера (с подтверждением кнопкой), бот уходит на паузу |
| `/report` | статистика: сделки, винрейт, профит-фактор, PnL, просадка. `/report 7` — за 7 дней |
| `/help` | список команд |

Пауза сохраняется в БД: после перезапуска бот останется на паузе, пока вы не отправите `/start`.

## Аварийная остановка

- **Из Telegram:** `/closeall` → «Да, закрыть всё».
- **С сервера** (если Telegram недоступен):
  ```bash
  docker compose exec bot python -m bot closeall --yes     # бот запущен
  docker compose run --rm bot closeall --yes               # бот остановлен
  ```

Аварийная остановка отменяет **все** algo-ордера и обычные ордера по SWAP, закрывает **все** позиции SWAP
на счёте по рынку и ставит бота на паузу. Возобновить торговлю: `/start`.

## Бэктест

```bash
docker compose run --rm bot backtest                  # 6 месяцев истории OKX, параметры из config.yaml
docker compose run --rm bot backtest --months 3 --symbols BTC-USDT-SWAP --balance 500
python -m bot backtest --csv-dir mydata/              # свои данные: <INST_ID>.csv с колонками ts,open,high,low,close,volume
python -m bot backtest --synthetic                    # синтетика без сети (только проверка механики)
```

История загружается с OKX (`/api/v5/market/history-candles`) и кэшируется в `data/history/`. Отчёт выводится
в консоль и сохраняется в `reports/` вместе с CSV всех сделок и кривой equity. Что в отчёте: число сделок,
винрейт, профит-фактор, максимальная просадка, итоговая доходность, средняя сделка в USDT и в R, комиссии,
фандинг, причины выходов, разбивка по инструментам.

Модель бэктеста консервативная:
- вход по открытию следующего бара после сигнала, с проскальзыванием;
- если в одном баре задеты и SL, и TP, считается, что первым сработал SL;
- при гэпе за уровень выход идёт по цене открытия бара;
- учитываются taker-комиссия 0.05% на вход и выход, проскальзывание 0.02% и фандинг 0.01% за 8 ч;
- размер позиции, лимит маржи, дневной лимит и максимум позиций считаются тем же кодом, что и в живой торговле.

> 💡 На 15-минутках стоп 1.5 ATR короткий, позиция получается крупной относительно депозита, и комиссии
> taker съедают заметную долю результата (порядка 0.1–0.2R на сделку). Смотрите в отчёте строку «Комиссии»
> и при необходимости пробуйте больший таймфрейм (`timeframe: 1H`) или более широкие стопы.

## Как заменить стратегию

Стратегия — отдельный модуль и ничего не знает о бирже. Она получает закрытые свечи и возвращает сигнал
с уровнями стопа, тейка и трейлинга. Размер позиции, SL/TP на бирже, трейлинг и лимиты берёт на себя ядро.
Создайте файл `bot/strategies/my_strategy.py`:

```python
from ..indicators import atr, ema
from . import register
from .base import ExitLevels, Signal, Strategy


@register
class Breakout(Strategy):
    name = "breakout"                       # это имя указывается в config.yaml
    defaults = {"lookback": 20, "atr_period": 14, "sl_atr": 2.0, "tp_atr": 4.0}

    @property
    def min_candles(self):
        return self.params["lookback"] + 2

    def compute(self, candles):             # индикаторы по всей истории, без заглядывания вперёд
        return {"atr": atr(candles.high, candles.low, candles.close, self.params["atr_period"])}

    def signal_at(self, candles, ind, i):   # сигнал на закрытии бара i (или None)
        n = self.params["lookback"]
        if i < n or ind["atr"][i] != ind["atr"][i]:
            return None
        if candles.close[i] > candles.high[i - n:i].max():
            price = float(candles.close[i])
            return Signal("long", price, int(candles.ts[i]),
                          self.exit_levels(candles, ind, i, "long", price), reason="пробой максимума")
        return None

    def exit_levels(self, candles, ind, i, side, entry_price):
        a, p = float(ind["atr"][i]), self.params
        sign = 1 if side == "long" else -1
        return ExitLevels(stop_loss=entry_price - sign * p["sl_atr"] * a,
                          take_profit=entry_price + sign * p["tp_atr"] * a, atr=a)
```

Затем укажите её в `config.yaml`:

```yaml
strategy:
  name: breakout
  params: {lookback: 30}
```

Файл подхватится автоматически. Проверьте стратегию бэктестом, затем перезапустите бота.

## Надёжность: что происходит при сбоях

| Ситуация | Поведение |
|---|---|
| Обрыв сети, таймаут, 5xx, техработы OKX | повтор с экспоненциальной задержкой (0.5 → 1 → 2 → 4 с…), потом следующий цикл |
| Rate limit OKX (50011 / HTTP 429) | встроенный лимитер ccxt с весами эндпоинтов, при ошибке — пауза и повтор |
| Таймаут при отправке ордера | перед повтором бот ищет ордер по `clOrdId`, дубля не будет |
| Перезапуск бота или сервера | позиции из БД и с биржи сверяются: свои продолжает сопровождать, чужие берёт на сопровождение, закрытые за время простоя записывает с PnL, дублей не открывает |
| SL/TP пропал с биржи | выставляется заново. Если цена уже за стопом, позиция закрывается по рынку |
| Прикреплённый SL/TP не появился после входа | выставляется отдельный TP/SL ордер. Если и это невозможно, позиция сразу закрывается |
| Amend трейлинга отклонён | ставится новый TP/SL, старый отменяется |
| WebSocket упал или молчит > 15 с | цены берутся через REST, WebSocket переподключается в фоне |
| Telegram недоступен | торговля продолжается, сообщения ждут в очереди |
| Торговый цикл завис > 10 мин | watchdog завершает процесс, Docker перезапускает контейнер |
| Неверные ключи или режим аккаунта | понятное сообщение в лог и в Telegram, повторы без «рестарт-шторма» |

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Что покрыто тестами:
- размер позиции (риск, комиссии, шаг лота, минимальный контракт, лимит маржи);

- сценарии торгового ядра на фейковой бирже: SL/TP на бирже, трейлинг, перезапуск и подхват позиций,
  восстановление SL, аварийное закрытие, гонки состояний;
- клиент OKX: ретраи, идемпотентность, demo-заголовок, формат запросов;
- бэктест и Telegram-команды.

Отдельный сквозной тест `tests/test_e2e_demo.py` запускает настоящий клиент ccxt против локального мока
OKX (REST и WebSocket). Мок проверяет HMAC-подпись каждого запроса и заголовок демо-торговли, отвечает
ошибками rate limit и нехватки маржи. Тест проверяет весь путь: вход, трейлинг, перезапуск, выход по тейку.

## Частые ошибки

| Код OKX / симптом | Причина и решение |
|---|---|
| `50101` APIKey does not match current environment | демо-ключ в LIVE или наоборот: проверьте `LIVE_TRADING` и где создан ключ |
| `50110` / `50111` / `50113` | IP сервера не в белом списке ключа, неверный ключ или подпись (проверьте secret и passphrase) |
| `50102` Timestamp request expired | расходятся часы: `sudo timedatectl set-ntp true` |
| `51008` Insufficient margin | мало свободного USDT на торговом счёте (переведите из Funding в Trading) |
| `51121` / `51020` | объём не кратен лоту или меньше минимального: бот это проверяет, увеличьте депозит |
| «Аккаунт OKX в режиме Spot» | переключите Account mode на Futures / Single-currency margin |
| Нет связи с OKX вообще | проверьте, доступен ли OKX из страны или региона VPS. Для региональных доменов OKX задайте `exchange.hostname` и WebSocket-адреса в `config.yaml` |
