# 🐈‍⬛ Meowgul — Telegram Mini App «тапалка + крипто-активы»

Игрок вместе с чёрным котом растит свою криптокомпанию от подворотни до небоскрёба: тапает кота,
собирает и прокачивает игровые крипто-активы (SOL, TON, BTC, ETH…) с пассивным доходом, поднимается по лигам,
зовёт друзей. Валюта — монеты **PAW** с отпечатком кошачьей лапы. Активы — игровые предметы, а не настоящая
криптовалюта и не инвестиции: их нельзя вывести, продать или перевести, кошельки не подключаются.

## Стек

- **frontend/** — React 18, Vite, TypeScript, Tailwind CSS, Zustand, Framer Motion
- **backend/** — Node.js 20, Fastify, TypeScript, Prisma, PostgreSQL, grammY (бот)
- **shared/** — общие типы API и форматирование чисел
- Тесты: Vitest (unit + интеграционные на тестовой БД), Playwright (e2e). CI — GitHub Actions.

## Персонажи (скины)

Скин — это отдельный персонаж: свой костюм и силуэт, свои цвета и аксессуары, свой мир-фон, атмосфера,
спокойная анимация и редкость. На главном экране надетый персонаж и есть кот, по которому тапают.

**20 персонажей** (`shared/src/cosmetics.ts`, оформление — `frontend/src/game/skins.ts`): первые 3 — бесплатно
у всех, следующие 3 — награды за лиги (выдаются сами, когда игрок доходит до лиги; в окне новой лиги их можно
сразу надеть), остальные 14 — за Telegram Stars без условий по уровню.

Редкость (COMMON … MYTHIC) — только внешний вид: скины не дают дохода, множителей и наград. Бесплатные скины и
награды за лиги не хранятся в базе — владение считается по лиге игрока (`progressCosmetics`); купленное раньше
за монеты остаётся у игрока. За монеты продаются только эффекты тапа (симулятор экономики покупает их, когда
они стоят не больше 4 часов дохода); без скинов за монеты 80% прогресса — на 204-й день вместо 206-го.

**Арт** — `frontend/public/assets/skins/<id>/`:
`character.{avif,webp}` (персонаж с прозрачным фоном, в своём разрешении), `background.{avif,webp}` (его мир
без персонажа, продлённый за края), `preview.{avif,webp}` (картинка карточки 640×800, 4:5), `icon.webp` (портрет). Геометрия (пропорции,
голова, центр тела) — `frontend/src/game/skinArt.json`. Эффекты сцены — CSS, отдельных файлов нет.

Сборка арта (один раз, результат в git; на Render не запускается):
- исходники — лист коллекции `frontend/assets-src/skins/collection.png` (плитка персонажа ~250 px) и карточки
  высокого разрешения `frontend/assets-src/skins/hires/<id>.webp` (896×1152, оригиналы без сжатия — lossless
  WebP; есть для 9 персонажей);
- `python3 frontend/scripts/skins/compose.py` — маска персонажа (BiRefNet через rembg, при необходимости
  доуточнение GrabCut) и раскладка строятся по апскейлу ×4 плитки (Real-ESRGAN anime) или по самой карточке;
  место персонажа, мини-превью и уголки рамки дорисовывает big-lama (LaMa), сцена плавно продлевается за края.
  Пиксели персонажа, фона и портрета берутся из **HD-слоя ×2** к той же раскладке: для плитки листа —
  SwinIR-L ×4 по исходной плитке, затем Real-ESRGAN ×2; для карточки — Real-ESRGAN ×2 по оригиналу. Модели
  (GitHub-релизы) скачиваются при первом запуске (`pip install rembg spandrel opencv-python-headless torch`);
- `node frontend/scripts/skins/build.mjs` — кодирование в AVIF/WebP **в нескольких размерах**
  (`frontend/src/game/skinSizes.json`: персонаж 600/900/1200/1600 px по высоте, фон 1200/1800/2400/3000, фон
  карточки 480/720/960 по ширине; только уменьшение) и манифест; затем `python3 frontend/scripts/skins/face.py`
  (лицо в манифест).
- Игра берёт наименьший файл, которого хватает месту на экране в пикселях экрана (CSS px × devicePixelRatio):
  персонаж на главном экране телефона ×3 — 1200 px, в окне персонажа — 900 px, в карточке — 600 px (`srcset`).
  Браузер ничего не растягивает (раньше персонаж 830–1030 px показывался на ~1040–1200 px экрана — мыло), а
  маленький экран не грузит лишнего. Юнит-тест проверяет, что в каждом файле ровно столько пикселей, сколько
  обещает имя, e2e — что файл не меньше места на экране.
Новая карточка высокого разрешения → положить в `hires/`, добавить строку в `HIRES` (`compose.py`) и пересобрать.
Для 11 персонажей с листа исходник — плитка ~250 px: HD-слой дорисован нейросетью; для максимальной детальности
нужны их оригиналы в высоком разрешении (как 9 карточек в `hires/`).

Иконки приложения, экран загрузки, превью ссылки и картинка приветствия бота собираются из стартового
персонажа (`npm run assets -w frontend`, запускается в `dev`/`build`).

**Главный экран** (`frontend/src/components/hero/`): `SkinScene` (мир персонажа: фон стоит так, что персонаж
находится точно на своём месте в своём мире и закрывает его на картинке — размытых мест не видно; свечение в
цвете скина, частицы атмосферы; падающие частицы летят с одним ветром на всю сцену) → `HeroStage` (тап) → `HeroFigure` (персонаж) → `tapEngine`
(энергия, награда, баланс — существующая логика).
- Персонаж и есть кнопка игры: зона тапа — вся высота сцены и ширина персонажа с запасом (в 1,5 раза, не уже
  60% сцены), ссылок и `<img>` в ней нет — долгое нажатие не открывает меню картинки.
- Покой и тап разделены полностью. В покое персонаж живёт: дышит (свой бесшовный CSS-цикл у каждого скина,
  от ступней — стоит на месте), водит глазами, иногда наклоняет голову, смотрит на лапы или вверх; блик
  и тень по силуэту; через 45 с без тапов — сон (взгляд вниз, персонаж тускнеет). Глаза не закрываются.
  Персонаж — самый резкий слой: без поворотов в объёме (они пересэмплировали картинку на каждом кадре),
  позиция и высота — в целых пикселях экрана; свечение и тень — отдельные слои под ним.
- Тап персонажа **не двигает**: ни прыжка, ни сжатия, ни тряски. Отвечает взгляд — в сторону пальца —
  и интерфейс: «+N», вспышка, кольцо, частицы эффекта тапа и всплеск в стиле персонажа
  (лепесток, искра, снежинка…) из пулов элементов.
- Лицо (`skinArt.json → face`, разметка — `frontend/scripts/skins/face.py`): эллипсы глаз, эллипс головы и
  точка шеи. `HeroFigure` собирает персонажа из той же картинки: тело с «окном» под голову, голова (наклон
  вокруг шеи) и радужка в глазу (взгляд: transform прямо на картинке в окошке глаза) — без новых картинок;
  в покое слои совпадают пиксель в пиксель.
- Смена скина: персонаж и мир мягко проявляются (0,4–0,5 с), картинки нового скина грузятся параллельно с
  запросом на сервер.
- Производительность: анимации — только transform/opacity; отдельный слой видеокарты — только у того, что
  движется постоянно (дыхание персонажа): голова, глаза, свет и тень рисуются внутри, без режимов
  наложения; пулы эффектов тапа и полёта монет получают слой только на время анимации; холст конфетти скрыт,
  пока частиц нет (главный экран в покое — 60 кадров/с при 4-кратном замедлении процессора, слоёв 46 вместо
  103). Вкладки переключаются без наложения двух экранов: старая исчезает сразу, новая проявляется за 150 мс;
  экраны поверх вкладки въезжают справа (300 мс, кривая drawer). Грузятся картинки только надетого скина (сетка
  коллекции — лениво, карточки 640×800 в пропорции 4:5 — без растягивания); AVIF через `image-set`, иначе WebP.
- Без лишней работы на каждом кадре: космический фон неподвижен (без гироскопа, мерцания и падающих звёзд),
  свечения за персонажем не пульсируют, рамки редкости в сетке статичные (живая — только у открытого
  предмета), шапка Airdrop без вращения, подсветка вкладок и нижнего меню — CSS без анимации раскладки,
  плитки активов без каскада и JS-анимаций на каждой, нажатия в длинных сетках — CSS (`.press`), полосы
  прогресса — `transform`. Что ниже экрана в длинных списках, не раскладывается и не рисуется
  (`content-visibility: auto`). Слабое устройство (≤4 ядер, ≤3 ГБ памяти, экономия
  трафика) — меньше частиц; «упрощённые анимации» — всё статично.

## Локальный запуск

Нужны Node.js 20+ и PostgreSQL 16 (проще всего через Docker).

```bash
npm install                    # зависимости всех пакетов
npm run db:up                  # PostgreSQL в Docker (или своя БД)
cp .env.example backend/.env   # при необходимости поправьте DATABASE_URL
npm run db:migrate             # миграции
npm run dev                    # API на :3000 и фронтенд на :5173
```

Откройте http://localhost:5173. Вне Telegram в development-режиме вход моковый: сервер выдаёт initData,
подписанный тестовым токеном (`GET /api/dev/init-data`, в production этого маршрута нет). Параметры игрока
задаются в адресе: `?uid=123&name=Мурка&premium=1&lang=en&ref=ref_456`.

## Авторизация

Клиент отправляет `Telegram.WebApp.initData` в заголовке `Authorization: tma <initData>`. Сервер проверяет
подпись HMAC-SHA256 токеном бота и свежесть `auth_date` (не старше 24 ч); без этого любой `/api/*` отвечает 401.
Дополнительно проверяются версия клиента (`X-Client-Version`, ответ 426) и режим техработ (503, админы проходят).

### Экономика и скорость прогресса

Игра рассчитана на долгую прогрессию: обычный активный игрок (4 захода в день, пропуск раз в неделю,
шифр и комбо не каждый день, друзья появляются постепенно) берёт ~80% общего прогресса за 6–7 месяцев,
последние 20% — долгий эндгейм (100% — около 3,5–4 лет).

| Срок | Общий прогресс | Доход в час | Лига | Уровень игрока |
|---|---|---|---|---|
| 1 неделя | ~16% | ~0,5 млн | Platinum | 11 |
| 1 месяц | ~38% | ~17 млн | Epic | 22 |
| 3 месяца | ~61% | ~125 млн | Legendary | 31 |
| 6 месяцев | ~77% | ~355 млн | Grandmaster | 37 |
| 7 месяцев | ~80% | ~410 млн | Grandmaster | 40 |
| 1 год | ~91% | ~600 млн | Lord | 44 |

- **Общий прогресс** (`backend/src/game/progress.ts`): 60% — доля купленных уровней всех активов,
  20% — лига, 20% — уровень игрока. Таблица выше — для игрока, открывающего активы за Stars; бесплатный игрок
  растёт на активах за монеты (доход растёт месяцами, покупка всегда в пределах суток-двух).
- **Активы** (`TIERS` в `backend/src/game/config/cards.ts`): у каждого тира задана окупаемость первого
  уровня (5 ч у дешёвых → 240 ч у самых дорогих) и последнего (3 000 ч → 60 000 ч); рост цены уровня
  подбирается так, чтобы окупаемость шла плавно, без «стены». Ни один уровень не даёт больше 2 млн/ч.
- **Комбо и шифр** — часы дохода игрока (3 ч и 1 ч, минимум 50 тыс. и 10 тыс.), а не фиксированные
  5 млн и 1 млн: в начале игры они не обесценивают активы, а позже остаются заметной наградой.
- **Ежедневная награда** — небольшой бонус за серию (весь 10-дневный цикл ≈ 120 тыс.).
- **Лиги и уровень игрока** — по всего заработанному; пороги подобраны под ту же кривую (Epic ~1 мес,
  Master ~4 мес, Lord ~8–9 мес; уровень 40 ~7 мес, 50 — эндгейм).
- `npm run economy-sim -w backend` — симуляция игрока по дням на настоящем конфиге (`-- --solo` — ещё и
  без друзей); `backend/test/economy.test.ts` держит кривую в рамках.
- Если цифры активов меняются для уже работающей игры, повышают `CARDS_ECONOMY_VERSION`
  (`backend/src/services/cards.ts`): при следующем старте сервер один раз перезапишет активы из конфига
  и пересчитает доход в час всех игроков по купленным уровням. Версия 4 — переход с карточек на крипто-активы:
  старые карточки (id с префиксами `mk_`, `pr_`, `lg_`, `sp_`, `lt_` — `LEGACY_CARD_ID`) удаляются, а все монеты, потраченные на их уровни, возвращаются игрокам
  на баланс (без роста лиги); комбо сегодняшнего дня со старыми карточками выбирается заново.

E2E-тесты поднимают API на отдельной базе `meowgul_e2e` (скрипт подготовки работает только с базами,
имя которых оканчивается на `_e2e`/`_test`) и production-сборку фронтенда в режиме `e2e`.

**Сценарии игры** (`frontend/e2e/scenarios`, `npm run test:e2e:scenarios`) — путь игрока целиком, с проверкой
и на экране, и в базе. Общие шаги — `fixtures.ts`: игрок с нужным состоянием, настоящие касания через CDP
(в том числе несколькими пальцами), баланс и энергия с экрана, ожидание засчитанных сервером тапов, вкладки
и «Назад» (Escape — как BackButton Telegram).

| Файл | Что проверяет |
|---|---|
| `first-day` | обучение → стартовый бонус и лига Silver → тапы (экран и сервер) → первый актив → ежедневная награда → бесплатный персонаж → профиль → всё сохраняется после перезапуска |
| `tap-mechanics` | мультитач (каждое касание — тап), пустая энергия и восстановление, Turbo ×5 на минуту без трат энергии, тапы без связи доходят все и без пометки, перезапуск посреди тапов, тап сквозь окно |
| `progress` | тапы поднимают лигу: сцена, персонаж-награда надевается сразу; рейтинг лиги; уровень игрока |
| `economy` | уровни актива дороже и прибыльнее, пассивный доход, офлайн-доход (не больше 3 ч), Energy limit |
| `shop-collection` | монеты за Stars (лига не растёт), премиальный персонаж: покупка, надет, после перезапуска; закрытые награды за лигу; эффект за монеты |
| `social` | приглашение по ссылке: бонус обоим, друг в списке; ссылка копируется |
| `navigation` | все вкладки по одной, «Назад»: окно → экран → главная, с любой вкладки; игра не сдвигается вбок |
| `mobile` | 360/375/390/412/430 px и 360×640 при ×3: экраны не прокручиваются вбок, меню на месте, скины на главной, в магазине, коллекции и окне не растянуты, нет 404; все 20 персонажей на главной — файл не меньше места на экране |

## Деплой на Render

В репозитории есть `render.yaml` (Blueprint): PostgreSQL `meowgul-db`, API `meowgul-api` (Web Service,
Node 20) и игра `meowgul-web` (Static Site).

**1. Бот в @BotFather**
- `/newbot` → имя и username бота (например, `meowgul_bot`). Сохраните токен — это `BOT_TOKEN`.
  Токен — секрет: только в переменных Render или в `backend/.env` (он в `.gitignore`), никогда в коде.
- Узнайте свой Telegram ID (например, у @userinfobot) — для `ADMIN_TELEGRAM_IDS`.

**2. Blueprint на Render**
- Render → **New → Blueprint** → выберите репозиторий; Render прочитает `render.yaml`.
- Заполните переменные, которые Render спросит (`sync: false`):

| Сервис | Переменная | Значение |
|---|---|---|
| meowgul-api | `BOT_TOKEN` | токен из BotFather |
| meowgul-api | `BOT_USERNAME` | username бота без `@` |
| meowgul-api | `WEBAPP_URL` | адрес игры, например `https://meowgul-web.onrender.com` |
| meowgul-api | `ADMIN_TELEGRAM_IDS` | ваш Telegram ID (несколько — через запятую) |
| meowgul-api | `CHANNEL_ID`, `CHANNEL_URL` | канал для задания «Подпишись»: `@channel` и `https://t.me/channel` (можно пусто) |
| meowgul-web | `VITE_API_URL` | адрес API, например `https://meowgul-api.onrender.com` |
| meowgul-web | `VITE_BOT_USERNAME` | username бота без `@` |

  Остальное задано в `render.yaml`: `DATABASE_URL` (из базы), `NODE_ENV=production`, `BOT_ENABLED=true`,
  `DAILY_RESET_UTC_HOUR=16`, случайный `WEBHOOK_SECRET`, `MINIAPP_SHORT_NAME=app`. `API_URL` задавать не нужно —
  на Render это адрес сервиса (`RENDER_EXTERNAL_URL`). Если имя сервиса занято и Render дал другой адрес,
  исправьте `WEBAPP_URL`/`VITE_API_URL` и нажмите **Manual Deploy**.
- Что происходит при деплое API: `npm ci` → сборка → `prisma migrate deploy` (одна миграция `init`) → старт.
  При старте сервер добавляет карточки и встроенные задания, ставит вебхук бота
  `API_URL/api/bot/webhook` с секретным заголовком, команды, описание и кнопку меню **Play**.
- Статика: сборка с `VITE_API_URL`; рядом с игрой создаётся `tonconnect-manifest.json` (адрес — из
  `RENDER_EXTERNAL_URL`, свой можно задать в `VITE_TONCONNECT_MANIFEST_URL`). Все пути переписываются
  на `index.html` (`/* → /index.html`), файлы сборки из `/build/*` кешируются навсегда.
- CORS: API принимает запросы только с `WEBAPP_URL` (дополнительные домены — `CORS_ORIGINS` через запятую).

**3. Mini App в @BotFather** (когда игра открылась по адресу `WEBAPP_URL`)
- `/newapp` → выберите бота → название, описание, картинка 640×360 → **Web App URL** = `WEBAPP_URL` →
  короткое имя `app` (= `MINIAPP_SHORT_NAME`). Ссылка на игру: `https://t.me/<бот>/app`, реферальные ссылки
  строятся от неё.
- Menu Button бот настраивает сам при запуске. Вручную: `/mybots` → бот → Bot Settings → Menu Button → URL.
- Для задания «Подпишись на канал» добавьте бота администратором канала.

**4. Проверка**
- `https://<api>/health` → `{"status":"ok"}`.
- Откройте бота → `/start` → **Играть**: вход проходит сам, офис открывается.
- `https://<игра>/admin` из Telegram под админским аккаунтом — админ-панель.

**5. Свой домен** — добавьте его в Render у `meowgul-web`, поменяйте `WEBAPP_URL` у API и URL Mini App в
BotFather (`/myapps` → Edit Web App URL).

> ⚠️ **Бесплатные планы Render — только для проверки.** Бесплатный Web Service засыпает через 15 минут
> без запросов: первый ответ приходит через ~50 секунд, бот в это время молчит, уведомления и рассылки не
> отправляются. Бесплатная база PostgreSQL удаляется через 30 дней. Для реальных игроков переключите
> `meowgul-api` на Starter или выше и базу — на платный план (с бэкапами).

## Крипто-активы

Экран «Активы» (бывший Mine). Вся экономика — в `backend/src/game/config/cards.ts` (в коде и БД активы
по-прежнему «карточки»): 59 активов в четырёх категориях — **Блокчейны** (TON, ADA, XRP, … SOL, BNB, ETH, BTC),
**DeFi** (LINK, UNI, … AAVE), **Мемы** (DOGE, NOT, … MEOW) и **Особые** (крипто-инфраструктура кота) — плюс
10 лимитированных **событий** (халвинг, бычий забег, сезон аирдропов…). У токенов — своя стилизованная монета
с тикером (`token/ТИКЕР/палитра`), без логотипов настоящих проектов.

- цена уровня n — `round(baseCost × costMultiplier^(n−1))`;
- прибыль за уровень n — `round(baseProfit × profitMultiplier^(n−1))` (доход ускоряется с уровнем);
- окупаемость `payback_time = цена уровня / прирост дохода в час`: у каждого **тира** (1–6) задана окупаемость
  первого уровня (5 ч → 240 ч) и последнего (3 000 ч → 60 000 ч), рост цены подбирается так, чтобы она шла
  плавно, без «стены» и без уровня выгоднее предыдущего. Ни один уровень не даёт больше 2 млн/ч.
- редкость (обычный / редкий / эпический / легендарный) — от тира; максимальный уровень: токены 25,
  особые 20, события 10 (`ASSET_MAX_LEVEL`).

**Открытие (`ASSET_UNLOCK`)**: 6 самых дешёвых активов открываются за монеты, остальные — за Telegram Stars,
и цена в Stars растёт в том же порядке, что и цена в монетах (от 5 ⭐ до 750 ⭐, каждая следующая строго
дороже; правится в админке). Звёздами покупается только 1-й уровень — дальше прокачка за монеты. Условия
открытия (`card`, `friends`, `task`, `league`) действуют и для платных активов: счёт выставляется, только когда
условие выполнено (`POST /api/cards/:id/invoice`), повторная покупка и оплата уже открытого актива отклоняются
ещё до оплаты. Возврат Stars в админке забирает актив и его доход, монеты за уровни со 2-го возвращаются.
Комбо дня собирается только из активов за монеты. В режиме разработчика платные активы открываются за монеты.

Прибыль в час игрока — сумма прибыли купленных уровней; пассивный доход начисляется сервером при каждом
запросе за время с прошлой синхронизации, но не больше 3 часов. Кулдауны — от 1 до 8 часов у дорогих активов.

**Как добавить актив:** допишите его в нужный массив в `cards.ts` (id, тир, иконка `token/ТИКЕР/палитра` или
`рисунок/значок/палитра`, названия и описания RU/EN, условие, кулдаун), запустите `npm run balance-check` и
`npm test` — тесты проверят уникальность id и тикеров, окупаемость, порядок цен в Stars и ссылки условий.
После деплоя сервер сам добавит новый актив в БД при старте.

**Как сменить баланс игры:** все числа — в `backend/src/game/config/*.ts` (`game.ts` — тап, энергия,
пассивный доход; `boosts.ts`; `leagues.ts`; `cards.ts` — `TIERS`, `ASSET_UNLOCK`, `ASSET_MAX_LEVEL`). Активы в
работающей игре хранятся в БД: после правки конфига повысьте `CARDS_ECONOMY_VERSION` или выполните
`npm run db:seed -- --force` — значения перезапишутся из конфига.

**События (лимитированные активы):** если в админке не задано окно `availableFrom`–`availableUntil`, событие
участвует в автоматической ротации (`LIMITED_ROTATION`: всегда 2 в продаже по 72 часа, по кругу). Купленное
событие продолжает приносить доход и после окна, но улучшать его можно только в следующее окно.

## Лиги и рейтинг

10 лиг по **всего заработанным** монетам (траты лигу не понижают): Bronze 0, Silver 5K, Gold 25K,
Platinum 100K, Diamond 1M, Epic 2M, Legendary 10M, Master 50M, Grandmaster 100M, Lord 1B — пороги и цвета
в `backend/src/game/config/leagues.ts`. Лига пересчитывается в единой функции изменения баланса, повышение
вызывает обработчики `onLeagueUp` (бонусы пригласившему — фаза 9).

`GET /api/leagues/:level/top` — топ-100 лиги, число игроков и место текущего игрока. Рейтинг собирается
SQL-запросом по индексу `(leagueLevel, totalEarned)` и кэшируется на минуту в памяти процесса; место игрока
вне топ-100 считается отдельным запросом и тоже кэшируется на минуту. Заблокированные игроки в рейтинг
не попадают.

## Earn: ежедневная награда и задания

**Ежедневная награда** — 10 дней подряд: 500, 1K, 2,5K, 5K, 15K, 25K, 100K, 500K, 1M, 5M
(`backend/src/game/config/rewards.ts`). Пропустил игровой день — серия начинается с Дня 1, после Дня 10
цикл начинается заново. Игровой день сбрасывается в `DAILY_RESET_UTC_HOUR` по UTC (16 = 19:00 по Киеву).
`POST /api/daily-reward/claim`; состояние приходит в `state.daily`.

**Задания** хранятся в таблице `Task`. При старте сервер создаёт встроенные (`backend/src/game/config/tasks.ts`):
«Подпишись на канал» (включается, когда заданы `CHANNEL_ID` и `CHANNEL_URL`; бот должен быть администратором
канала — подписка проверяется через Bot API `getChatMember`) и «Пригласи 3 друзей» (проверка по БД).
**Как добавить задание:** в админке, вкладка «Задания» (ссылки на соцсети, видео, спецпредложения,
подписка на другой канал), или через API админки:

| Метод | Что делает |
|---|---|
| `GET /api/admin/tasks` | все задания и сколько игроков их выполнили |
| `POST /api/admin/tasks` | создать: `id`, `type` (`TELEGRAM_CHANNEL`, `LINK`, `VIDEO`, `INVITE_FRIENDS`, `CHOOSE_HQ`, `CONNECT_WALLET`), `section` (`SPECIAL`, `LIST`, `AIRDROP`), названия и описания RU/EN, `icon`, `url` (только https), `channelId`, `requiredCount`, `reward`, `checkDelaySec` (по умолчанию 30), `sortOrder`, `isActive` |
| `PUT /api/admin/tasks/:id` | изменить |
| `DELETE /api/admin/tasks/:id` | удалить; если задание уже кто-то выполнил — только выключить |

Задания-ссылки (`LINK`, `VIDEO`) можно проверить через `checkDelaySec` секунд после перехода
(`POST /api/tasks/:id/start` → `POST /api/tasks/:id/check`). Награда начисляется один раз — параллельные
проверки и повторные запросы ничего не добавляют.

## Комбо дня и шифр

**Комбо дня** — 3 актива, загаданные на игровой день. Если за день игрок улучшит все три — **+5 000 000**
(награды — `backend/src/game/config/rewards.ts`). Админ задаёт комбо на неделю вперёд
(`PUT /api/admin/combo/:dayKey { cardIds }`); если не задал — сервер при первом обращении выбирает случайно
по одному активу из трёх разных категорий среди открываемых за монеты (без событий, условий друзей/лиг/заданий
и не дороже 300K за первый уровень). На экране «Активы» угаданные открываются в слотах, остальные — «?».

**Шифр дня** — слово из 4–7 латинских букв, вводится азбукой Морзе тапами по коту: короткое касание — точка,
нажатие дольше 0,3 с — тире, пауза 0,9 с — следующая буква. Награда **+1 000 000**. Слово не уходит на клиент:
игрок видит подсказку и число букв, проверку делает сервер (`POST /api/cipher/claim { word }`). Слова с
подсказками — `backend/src/game/config/ciphers.ts`; админ может задать своё (`PUT /api/admin/cipher/:dayKey`).
`GET /api/admin/daily` — комбо и шифры на 7 дней вперёд. `GET /api/combo` — комбо и шифр текущего дня для игрока.

## Друзья и рефералы

Реферальная ссылка игрока: `https://t.me/<BOT_USERNAME>?start=ref_<telegramId>` — открывает бота, он
запоминает пригласившего (`PendingReferral`, первое приглашение действует 7 дней) и даёт кнопку «Играть».
Ссылки Mini App вида `t.me/<бот>/<short_name>?startapp=ref_…` тоже работают (нужен `/newapp` в BotFather).
При **первом** входе (по `start_param=ref_…` или по сохранённому ботом приглашению) оба получают бонус: +5 000, а если у нового игрока Telegram
Premium — +25 000. Пригласить себя нельзя, уже зарегистрированный игрок по ссылке не засчитывается,
заблокированный пригласивший бонусов не получает. Когда друг достигает новой лиги, пригласивший получает
бонус за каждую пройденную лигу один раз (Silver +20K, Gold +30K, Platinum +40K, Diamond +60K, Epic +95K,
Legendary +195K, Master +400K, Grandmaster +800K, Lord +2M; за Premium-друга — вдвое больше).
Все суммы — `REFERRAL` в `backend/src/game/config/rewards.ts`.

`GET /api/friends?after=<id>` — ссылка, таблица бонусов, сколько всего получено и список друзей по 50
(у каждого — уровень, лига и «в сети», если заходил за последние 10 минут). Источник истины — сервер:
экран друзей показывает загрузку, пустой список и ошибку с кнопкой «Повторить».

## Airdrop и кошелёк TON

Вкладка Airdrop (`GET /api/airdrop`): очки Airdrop (= всё заработанное), место среди игроков (пересчёт
раз в 30 с), готовность в процентах и требования — лига Platinum, уровень 10, 3 друга, серия входов 7 дней,
6 активов (все, что открываются за монеты), 5 заданий (`AIRDROP_TARGETS` в `backend/src/routes/airdrop.ts`), а ниже — задания раздела `AIRDROP`
из админки.

**Кошелёк TON скрыт флагом** `TON_WALLET_ENABLED = false` (`shared/src/features.ts`): нет кнопки
подключения, задания «Подключи кошелёк» и достижения за кошелёк, библиотека TON Connect не загружается —
вместо неё строка «Подключение кошелька — скоро». Бэкенд, поля в базе и API кошелька сохранены: чтобы вернуть
кошелёк, поставьте `true` и пересоберите игру.

Как работает кошелёк при включённом флаге: TON Connect (`@tonconnect/ui-react`, отдельный модуль
`WalletCard.tsx`). Владение кошельком подтверждается
**ton_proof**: сервер выдаёт подписанный payload на 15 минут (`GET /api/wallet/proof-payload`), кошелёк
подписывает адрес, домен игры, время и payload, сервер сверяет адрес с `stateInit`, берёт из него публичный
ключ (кошельки v3/v4/v5) и проверяет подпись ed25519 (`POST /api/wallet`). Домен должен совпадать с
`WEBAPP_URL`/`CORS_ORIGINS`, в production принимается только mainnet. Один кошелёк — один игрок.
`DELETE /api/wallet` — отключить. Манифест TON Connect отдаёт API: `GET /api/tonconnect-manifest.json`
(название, адрес и иконка игры из `WEBAPP_URL`); другой адрес манифеста можно задать в
`VITE_TONCONNECT_MANIFEST_URL`.

## Бот

Бот на grammY (`backend/src/bot/`) включается переменными `BOT_ENABLED=true` и `BOT_TOKEN`.
- `/start` — приветствие с космической картинкой (`assets/generated/welcome.jpg`, собирается вместе с игрой), кратким
  списком возможностей, кнопкой **Play** (Mini App) и кнопкой канала, если задан `CHANNEL_URL`.
  `/start ref_<telegramId>` (реферальная ссылка) запоминает пригласившего, если игрок ещё не играл; бонус
  начисляется при первом входе в игру. Кнопка **Play** — всегда `web_app`, работает без `/newapp`.
  Тексты на русском и английском — по языку Telegram (`backend/src/bot/texts.ts`).
- При запуске бот сам ставит команды, описание «Что умеет этот бот?» (по-русски — и для украинского, белорусского
  и других языков из `RU_LANGS`) и кнопку меню **Play**. Повторно — только если тексты или адрес игры изменились.
- В production — вебхук `API_URL/api/bot/webhook`. Telegram передаёт секрет в заголовке
  `X-Telegram-Bot-Api-Secret-Token`: hex-значение, производное от `WEBHOOK_SECRET` (или от токена, если он не
  задан) — Telegram принимает в секрете только латиницу, цифры, `_` и `-`.
  В разработке — long polling. Если Telegram недоступен, бот повторяет попытку каждые 30 секунд, игра при
  этом работает.

## Уведомления

Уведомления отправляет очередь `Notification`, её обрабатывает воркер каждую секунду.
- Пишем только тем, кто разрешил: нажал `/start` или дал доступ в Mini App, и не выключил уведомления в
  настройках.
- Не больше 2 сообщений игроку за игровой день и не больше 25 сообщений в секунду. Сообщения старше 6 часов
  не отправляются.
- Если игрок заблокировал бота, уведомления ему выключаются. На ответ 429 очередь ставится на паузу.
- Поводы: энергия восстановилась (если игрок потратил её почти до нуля), вышло новое комбо дня (игрокам,
  которые заходили за последние 3 дня), по твоей ссылке пришёл друг.

## Онбординг и штаб-квартира

При первом входе — 3 слайда: тапай, карточки и пассивный доход, друзья. Затем выбор штаб-квартиры
котокомпании из 6 мест (`shared/src/hq.ts`). За выбор — **+5 000** один раз (встроенное задание
«Выбери штаб-квартиру»). Штаб-квартира видна в шапке Офиса. Онбординг можно пропустить. Сменить
штаб-квартиру можно потом, но награда повторно не начисляется (`POST /api/hq { hqId }`).

## Профиль, достижения и настройки

**Достижения** — 60 штук в пяти группах (прогресс, бизнес, друзья, каждый день, особые). Список, пороги и
награды — `shared/src/achievements.ts`: у каждого есть показатель (тапы, заработок, прибыль в час, лига,
карточки, друзья, серия ежедневки, комбо, шифры, задания, золотые монеты, дни в игре…) и порог.
Выдаёт только сервер (`backend/src/services/achievements.ts`):
- показатели из строки игрока проверяются после **каждого** изменения баланса;
- подсчитываемые (карточки, друзья, задания и т.д.) — в маршрутах, где они меняются, и все сразу при входе.
  Поэтому новое достижение, добавленное в конфиг, игроки получат при следующем входе.

Награда начисляется через общий журнал (`achievement_reward`). Если награда открывает следующее
достижение (например, поднимает лигу), оно выдаётся в том же запросе. Новые достижения приходят в
`state.achievements.fresh`: клиент показывает всплывающую плашку и отмечает их просмотренными
(`POST /api/achievements/seen`).

**Профиль** (`GET /api/profile`): статистика (тапы, заработано, дни в игре, лучшая серия, друзья,
карточки, комбо, шифры) и все достижения с датой получения или прогрессом.

**Настройки** (`PATCH /api/settings`): язык (авто/русский/английский), звук, вибрация, анимации
(полные/упрощённые), уведомления бота. Там же — смена штаб-квартиры и **удаление аккаунта**
(`POST /api/account/delete { confirm: true }`, кнопка активна через 3 секунды). Удаляется весь прогресс.
Telegram ID запоминается: если игрок снова зайдёт по чьей-то ссылке, бонусы за приглашение не начислятся
(защита от накрутки).

## Мини-события и подсказки

**Счастливый час** — целый час каждый тап приносит ×2 (энергия тратится как обычно). Время начала
одинаково для всех: через 2–21 час после сброса дня, кратно 15 минутам (зависит от даты). Админ может
назначить дополнительный счастливый час с другим множителем или выключить автоматический (настройка
`happyHour` в `AppSetting`). Множитель считает сервер (`POST /api/tap`), клиент показывает таймер в Офисе.
Бот объявляет начало игрокам, которые заходили за последние 3 дня (с учётом лимита 2 сообщения в день).

**Золотая монета** — иногда после пачки тапов сервер выпускает монету (не больше 3 в игровой день и
не чаще раза в 20 минут). Она пробегает над котом или под ним за 3 секунды — по лицу персонажа не
проходит. Поймать: `POST /api/events/:id/claim`. Принимается только своя монета, один раз и пока она
на экране (+1,5 с на сеть). «Поймал» быстрее 0,25 с после появления — не человек: попытка отклоняется,
`suspiciousScore` растёт. Награда — четверть прибыли в час, минимум 1 000. Выключается настройкой
`goldenCoin`. Параметры — `backend/src/game/config/events.ts`.

**Подсказки вкладок** — при первом открытии Офиса, «Активов», Friends, Earn, Airdrop и Бустов затемнение
выделяет нужный элемент, рядом стрелка и текст, шаги листаются. Подсказки ждут, пока закроются онбординг,
модалки и сцены. Просмотр запоминается на сервере (`POST /api/tutorials/:id/seen`). Шаги —
`frontend/src/game/tutorials.ts`.

## Навигация

Нижнее меню: **Главная**, **Друзья**, **Магазин**, **Airdrop**, **Коллекция**, **Профиль**
(`frontend/src/components/BottomNav.tsx`). На главной под котом — энергия с полоской заряда, ниже кнопки «Активы»,
задания Earn и бусты быстрыми кнопками (точка на кнопке Earn — ежедневная награда ждёт). Экраны поверх вкладок
(«Активы», Earn, бусты, лиги, настройки) закрываются кнопкой «Назад» Telegram; на остальных вкладках «Назад»
ведёт на главную (аппаратная кнопка Android не закрывает игру с полпути). Оболочка игры обрезает содержимое
через `overflow: clip` — подсказка вкладки (`scrollIntoView`) во время въезда экрана не сдвигает всю игру вбок.

## Уровень игрока, скины и коллекция

**Уровень** 1–50 считается по монетам, заработанным за всё время (`shared/src/progression.ts`). Новый уровень —
тост и радость персонажа; уровни открывают эффекты тапа (персонажи — бесплатно, за лиги или за Stars).

**Коллекция** — вкладка нижнего меню (и раздел «Скины» в магазине): карточки персонажей 4:5 из слоёв — кадр
его мира (`card-*`), свет в цвете скина, тень под ступнями и сам персонаж отдельным резким слоем поверх
(`srcset` — файл под размер карточки), рамка и бейдж редкости, статус (надет / есть / закрыт), условие
получения и кнопка «Надеть» для своих. Нажатие на карточку — полный просмотр: крупный персонаж в полный рост в
своём мире с анимацией и атмосферой, редкость, имя, описание, «Как получить» с ценой и большая кнопка
(надеть / купить за ⭐ — золотая / закрыт: «🔒 Лига Gold»). Вторая вкладка — эффекты тапа.

API: `GET /api/collection` (бесплатные + награды за достигнутые лиги + купленные), `POST /api/collection/:id/buy`
(эффекты за монеты: уровень, цена и владение проверяет сервер, списание через ledger, покупка сразу
надевается), `POST /api/collection/:id/equip` (только своё: бесплатное, награда за лигу или купленное).
Надетый скин хранится на сервере (`User.equippedSkinId`) и возвращается в состоянии игрока — после перезагрузки
и на другом устройстве он тот же; неизвестный id показывается как стартовый. Премиальные персонажи покупаются
через магазин (`skin_<id>` для каждого из 14 персонажей за Stars, эффект — `effect_matrix`), при возврате
оплаты предмет забирается.

**Миграция со старой коллекции** (`backend/prisma/migrations/20261005120000_skin_characters`): старые
скины-перекраски удалены полностью. Купленные — заменены персонажами той же ценности (тот же источник и дата
покупки; таблица соответствия — `LEGACY_SKINS` в `shared/src/cosmetics.ts`), надетый старый скин сброшен на
стартового. Баланс, опыт, карточки, друзья и прогресс не меняются. Неоплаченный счёт или возврат по старому
товару выдаёт/забирает замену.

## Магазин за Telegram Stars

Вкладка **Магазин** в нижнем меню: разделы «Скины», «Активы» (крипто-активы за Stars — от дешёвых к дорогим,
с условием открытия, если оно ещё не выполнено), «Бусты», «Особое» (монеты), «Эффекты».
Цены и количества — `backend/src/game/config/shop.ts`, цены активов — `ASSET_UNLOCK` в `cards.ts` (и админка).

| Товар | Цена | Что даёт |
|---|---|---|
| Горсть / Мешок / Сейф монет | 25 / 100 / 250 ⭐ | 3 / 15 / 45 ч текущего дохода (минимум 25 000 / 150 000 / 500 000) |
| Полная энергия | 10 ⭐ | энергия сразу на максимум, сверх дневного лимита |
| Доход ×2 | 150 ⭐ | пассивный доход ×2 на 24 ч, повторная покупка продлевает |
| Ангел-Хранитель / Теневой Бродяга / Кибер-Самурай / Галактический Император | 149 / 249 / 299 / 399 ⭐ | премиальный персонаж |
| Эффект Matrix | 99 ⭐ | эффект тапа «цифровой дождь» |
| Крипто-актив | 5 … 750 ⭐ | 1-й уровень актива и его доход в час (дальше — прокачка за монеты) |

- Купленные монеты не идут в «всего заработано»: лигу и рейтинг купить нельзя.
- Оплата: `POST /api/shop/invoice` создаёт покупку (`Purchase`, PENDING) и счёт в XTR (`createInvoiceLink`),
  игра открывает его через `Telegram.WebApp.openInvoice`. Бот отвечает на `pre_checkout_query` (проверка суммы,
  покупателя и срока счёта), на `successful_payment` выдаёт покупку ровно один раз и пишет «Покупка зачислена».
  Игра ждёт выдачу по `GET /api/shop/purchases/:id`.
- `/paysupport` в боте (обязателен для ботов с оплатой): сообщение игрока уходит всем из `ADMIN_TELEGRAM_IDS`.
- Админка: покупки игрока с кнопкой «Вернуть» (`refundStarPayment`, монеты и время буста забираются) и звёзды
  в статистике. Звёзды выводятся через Fragment (Telegram держит их 21 день).
- Без настоящего токена вне production счёт — `dev-invoice://…`, оплату имитирует `POST /api/dev/shop/pay/:id`.
- ⚠️ Telegram ждёт ответ на оплату 10 секунд — спящий бесплатный сервер может не успеть. Для продаж переведите
  `meowgul-api` на тариф Starter.

## Админ-панель

Адрес — `WEBAPP_URL/admin`. Пускает только Telegram ID из `ADMIN_TELEGRAM_IDS`: сервер проверяет это на
каждом запросе `/api/admin/*`, обычный игрок получит 403. Открыть можно из игры (Настройки → Админ-панель
видна только админам) или по прямой ссылке внутри Mini App. В разработке — `http://localhost:5173/admin?uid=<ваш ID>`.
Код админки — отдельный чанк (`frontend/src/admin/`), игрокам он не загружается. Интерфейс на русском и
английском.

**Режим разработчика** — только для одного аккаунта: `DEVELOPER_TELEGRAM_ID` (Render → meowgul-api →
Environment), а если он не задан и админ в `ADMIN_TELEGRAM_IDS` один — для него; при нескольких админах без
этой переменной — ни для кого. Переключатель — Настройки → «Разработчик», его видит только этот аккаунт. Для
проверки игры: все скины и эффекты открыты и надеваются (в базе ничего не выдаётся), карточки без условий,
лимитированные — в любое время, откатов нет. Цены и баланс — как обычно; монеты можно начислить себе в
админ-панели (карточка игрока → начисление). Сервер проверяет владельца на каждом запросе: другой игрок или
другой админ включить режим не может, старый флаг в настройках у них ничего не даёт.

- **Статистика** (`GET /api/admin/stats`): всего игроков, новые за день, DAU/WAU/MAU, удержание D1/D7/D30
  по когортам (по последнему полному дню), монеты на руках и заработанные, баны, подозрительные, очередь
  уведомлений, график активных и новых за 14 дней, топ рефереров.
- **Игроки**: поиск по id, Telegram ID, @username и имени. Список подозрительных (`suspiciousScore ≥ 3`).
  Карточка игрока с журналом операций (постранично), ручное начисление или списание с причиной (пишется
  в журнал как `admin_adjustment` с ID админа), бан с причиной, разбан (сбрасывает подозрительность).
- **Карточки**: правка всех полей, иконка из каталога рисунков (без своих картинок и логотипов), условия
  открытия, окна продажи лимитированных. Превью цены, прироста и окупаемости по уровням и проверка правил
  баланса — сервером, по тем же формулам, что в игре. Удалить можно только карточку без владельцев, иначе —
  снять с продажи. Новая прибыль действует для новых покупок уровней.
- **Задания**: создание, правка, удаление (выполненное игроками задание выключается).
- **Комбо и шифр** на 7 дней вперёд (ещё не выбранные выбираются при открытии).
- **Рассылки** через бота: текст, картинка, кнопка-ссылка; превью; тест себе; запуск, пауза, продолжение,
  отмена; прогресс обновляется сам. Получают игроки, разрешившие боту писать и не выключившие уведомления.
  Рассылка делит с уведомлениями лимит 25 сообщений в секунду, переживает перезапуск сервера (позиция
  хранится в БД), на 429 от Telegram ждёт, заблокировавшим бота больше не пишет.
- **Настройки**: технические работы с сообщением (админы заходят как обычно), минимальная версия клиента,
  счастливый час (автоматический и дополнительный с множителем ×2–×5), золотая монета.

## Проверка качества

| Что | Результат | Как проверить |
|---|---|---|
| Unit и интеграционные тесты | shared 11, backend 204 (на тестовой БД), frontend 27 — все зелёные | `npm test` |
| E2E (Playwright) | 70 тестов экранов и механик + 29 сценариев игры (`e2e/scenarios`), включая главный: вход → тап → покупка карточки → ежедневка → друг, а также персонажи (бесплатные, награда за лигу в окне новой лиги, покупка за Stars, надевание, просмотр, смена мира, быстрое переключение, старый скин в базе), тапы без сети после перезапуска, двойной тап по «Купить», Airdrop и магазин | `npm run test:e2e` |
| Покрытие игровой логики | 96 % строк в `src/game`, `src/auth`, `src/services` (порог в конфиге — 80 %) | `npm run test:coverage -w backend` |
| Lighthouse, мобильный режим | Performance 92–95, Accessibility 94, Best Practices 96; CLS 0 | `npx lighthouse <адрес игры>` |
| Бандл главного экрана | ≈ 171 KB gzip (код 71 + React 43 + Framer Motion 45 + CSS 12); экраны и админка грузятся отдельно, TON Connect при выключенном флаге не попадает в сборку | `npm run build -w frontend` |
| Линтер, типы, формат | без ошибок и предупреждений | `npm run check` |

**Тапы не теряются**: если игру свернули или закрыли, пока пачка тапов ещё в пути или нет сети, неотправленные
тапы сохраняются на устройстве (`meowgul.unsent.<id>`) и уходят при следующем входе — пачка с тем же номером,
поэтому сервер не засчитает её дважды, даже если первый запрос всё же дошёл.
Пачка не больше, чем сервер примет за прошедшее время (`maxPerSecond` × секунд с прошлого ответа + запас, как
`tapAllowance` на сервере): после обрыва связи повтор старой пачки и накопленные тапы больше не попадают в доли
секунды — сервер не обрезает тапы и не помечает игрока, остаток уходит следующими пачками, баланс не откатывается.

**Кнопки с запросом** (купить актив, разблокировать за Stars, буст, задание, ежедневная награда, старт)
блокируются сразу при нажатии (`useBusy`, флаг в ref) — двойной тап не покупает уровень дважды.

**Защита от накрутки** проверена автотестами на каждый случай: двойной клик покупки, параллельные запросы,
подменённый и просроченный initData, отрицательные, дробные и огромные числа, повтор старой пачки тапов,
тапы скриптом быстрее 20 в секунду, слишком быстрая «ловля» золотой монеты, повторное приглашение после
удаления аккаунта.

**Экраны** проверяются на ширине 320, 375, 390 и 430 px (e2e `smoke`). Снимки всех экранов —
`SCREENSHOTS=<папка> npx playwright test screens` в `frontend/`. У игры своя тёмная «космическая» палитра,
шапку и фон Telegram она красит сама, поэтому в светлой и тёмной теме Telegram выглядит одинаково.

**Фон** — ночное небо с туманностью. Рисуется кодом (`frontend/src/lib/spaceSky.ts`, без картинок) порциями,
не мешая первым кадрам. Мерцающие звёзды, падающие звёзды и параллакс от наклона телефона — в
`SpaceBackground.tsx`; при «упрощённых анимациях» фон неподвижен.
