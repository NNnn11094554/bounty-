# 🐈‍⬛ Meowgul — Telegram Mini App «тапалка + карточки»

Игрок вместе с чёрным котом растит свою криптокомпанию от подворотни до небоскрёба: тапает кота,
покупает карточки с пассивным доходом, поднимается по лигам, зовёт друзей. Валюта — монеты **PAW**
с отпечатком кошачьей лапы.

> README дополняется по мере готовности фаз. Текущий статус — в [PROGRESS.md](PROGRESS.md).

## Стек

- **frontend/** — React 18, Vite, TypeScript, Tailwind CSS, Zustand, Framer Motion
- **backend/** — Node.js 20, Fastify, TypeScript, Prisma, PostgreSQL, grammY (бот)
- **shared/** — общие типы API и форматирование чисел
- Тесты: Vitest (unit + интеграционные на тестовой БД), Playwright (e2e). CI — GitHub Actions.

## Персонаж

Картинка кота лежит в `frontend/public/assets/character.png` (PNG 1254×1254) и используется как есть.
При сборке скрипт `frontend/scripts/optimize-images.mjs` делает из неё WebP 512/1024, PNG-фолбэк,
иконки и OG-картинку в `frontend/public/assets/generated/`. Если файла нет — положите `character.png`
в эту папку; до тех пор используется заглушка-круг того же размера.

## Локальный запуск

Нужны Node.js 20+ и PostgreSQL 16 (проще всего через Docker).

```bash
npm install                    # зависимости всех пакетов
npm run db:up                  # PostgreSQL в Docker (или своя БД)
cp .env.example backend/.env   # при необходимости поправьте DATABASE_URL
npm run db:migrate             # миграции
npm run dev                    # API на :3000 и фронтенд на :5173
```

Откройте http://localhost:5173. Вне Telegram в development-режиме вход моковый: сервер выдаёт initData,
подписанный тестовым токеном (`GET /api/dev/init-data`, в production этого маршрута нет). Параметры игрока
задаются в адресе: `?uid=123&name=Мурка&premium=1&lang=en&ref=ref_456`.

## Авторизация

Клиент отправляет `Telegram.WebApp.initData` в заголовке `Authorization: tma <initData>`. Сервер проверяет
подпись HMAC-SHA256 токеном бота и свежесть `auth_date` (не старше 24 ч); без этого любой `/api/*` отвечает 401.
Дополнительно проверяются версия клиента (`X-Client-Version`, ответ 426) и режим техработ (503, админы проходят).

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | API + фронтенд в режиме разработки |
| `npm run build` | production-сборка обоих пакетов |
| `npm test` | все unit- и интеграционные тесты |
| `npm run test:e2e` | e2e-тесты Playwright |
| `npm run lint` / `npm run typecheck` / `npm run format` | ESLint, `tsc --noEmit`, Prettier |
| `npm run check` | всё вместе — как в CI |
| `npm run db:seed` | добавить в БД карточки из конфига (`-- --force` — перезаписать их значениями конфига) |
| `npm run balance-check` | таблица окупаемости карточек до 25 уровня и проверка правил экономики |

E2E-тесты поднимают API на отдельной базе `meowgul_e2e` (скрипт подготовки работает только с базами,
имя которых оканчивается на `_e2e`/`_test`) и production-сборку фронтенда в режиме `e2e`.

## Карточки Mine

Экономика целиком в `backend/src/game/config/cards.ts`: 120 обычных карточек (по 30 в Markets, PR&Team,
Legal, Specials) и 15 лимитированных Specials. Формулы:

- цена уровня n — `round(baseCost × costMultiplier^(n−1))`, `costMultiplier` 1,7–2,2;
- прибыль за уровень n — `round(baseProfit × profitMultiplier^(n−1))`, `profitMultiplier` 1,05–1,2;
- `baseCost` и окупаемость первого уровня задаются **тиром** карточки (1–6) и множителем `k` внутри тира,
  `baseProfit = baseCost / окупаемость`. Окупаемость растёт с ~4–10 ч на первом уровне до 100+ ч к 10-му;
  дальше она резко растёт — поздние уровни работают как «мягкий потолок».
- Цена уровня не превышает 10^15: если карточка дорогая, её `maxLevel` уменьшается автоматически.

Прибыль в час игрока — сумма прибыли купленных уровней; пассивный доход начисляется сервером при каждом
запросе за время с прошлой синхронизации, но не больше 3 часов. Условия открытия (`card`, `friends`, `task`,
`league`) проверяются только перед первой покупкой. Кулдауны — от 10 минут до 24 часов после покупки уровня.

**Как добавить карточку:** допишите её в нужный массив в `cards.ts` (id, тир, иконка `рисунок/значок/палитра`
из `shared/src/cards.ts`, названия и описания RU/EN, условие, кулдаун), запустите `npm run balance-check` и
`npm test` — тесты проверят уникальность id и иконки, диапазоны множителей, окупаемость и ссылки условий.
После деплоя сервер сам добавит новую карточку в БД при старте. Новый рисунок — функция в
`frontend/src/components/cards/glyphs.tsx` (сетка 48×48) и имя в `CARD_GLYPHS`.

**Как сменить баланс игры:** все числа — в `backend/src/game/config/*.ts` (`game.ts` — тап, энергия,
пассивный доход; `boosts.ts`; `leagues.ts`; `cards.ts` — тиры `TIERS`). Карточки в работающей игре
хранятся в БД: после правки конфига выполните на сервере `node dist/seed.js --force` (или
`npm run db:seed -- --force` локально) — значения карточек перезапишутся из конфига. Уже купленные уровни
сохраняют прибыль, полученную при покупке.

**Лимитированные карточки:** если в админке у карточки не задано окно `availableFrom`–`availableUntil`, она
участвует в автоматической ротации (`LIMITED_ROTATION`: всегда 2 карточки в продаже по 72 часа, по кругу).
Купленная лимитированная карточка продолжает приносить доход и после окончания окна, но улучшать её нельзя
до следующего окна.

## Лиги и рейтинг

10 лиг по **всего заработанным** монетам (траты лигу не понижают): Bronze 0, Silver 5K, Gold 25K,
Platinum 100K, Diamond 1M, Epic 2M, Legendary 10M, Master 50M, Grandmaster 100M, Lord 1B — пороги и цвета
в `backend/src/game/config/leagues.ts`. Лига пересчитывается в единой функции изменения баланса, повышение
вызывает обработчики `onLeagueUp` (бонусы пригласившему — фаза 9).

`GET /api/leagues/:level/top` — топ-100 лиги, число игроков и место текущего игрока. Рейтинг собирается
SQL-запросом по индексу `(leagueLevel, totalEarned)` и кэшируется на минуту в памяти процесса; место игрока
вне топ-100 считается отдельным запросом и тоже кэшируется на минуту. Заблокированные игроки в рейтинг
не попадают.
